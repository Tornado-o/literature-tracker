# 可选集成与恢复

## 文献库

只归档最终核准的正式荐读。执行前确认已授权的文库和写入通道，按 DOI、预印本标识及规范化题名和作者查重。已有条目优先复用，追加归属时保留其他分类成员关系。导入后读回核对题名、作者、类型、可核准的日期和标识，以及实际所属分类。

### Zotero 本地与云端模式

**本地 Zotero。** 告诉用户：“请保持电脑在线、Zotero 桌面端在后台运行，可以最小化。” 如本地接口尚未开启，请用户在 Zotero 设置 → 高级允许本机其他应用与 Zotero 通信。建刊时探测，归档前再检查。可读取文库或通过 Connector 导入，并不意味着能创建分类。若当前本地工具无受支持的分类创建权限，说明“分类待创建”，用户可手动创建，或另行选择配置云端模式。目标分类核准后方可写入。

**Zotero 云端。** 桌面端不需要在归档时运行。给用户以下步骤：

1. 如果文献原本只在桌面端，先登录并同步一次，在 [Zotero 网页文库](https://www.zotero.org/library) 确认目标文库。
2. 到 [Zotero 密钥设置](https://www.zotero.org/settings/keys) 创建专用私有密钥。使用个人文库时，在 **Personal Library** 同时启用 **Allow library access** 和 **Allow write access**，群组权限选 **None**。个人写权限覆盖个人整库；若用户指定群组，仅授予目标群组所需权限。群组的 **Read/Write** 不会授予个人文库写权限。
3. 优先将密钥保存为运行账户的用户环境变量。Windows 可在“编辑账户的环境变量”中新建用户变量，默认名为 `ZOTERO_API_KEY`；已有项目可沿用其变量名。完全退出并重新启动执行客户端，使新进程读取更新。其他系统使用定时任务能够读取的私有环境或凭据存储。环境变量不是加密存储。若用户希望直接交给助手，只通过当前界面明确提供的保密凭据输入或密钥存储功能；没有这种入口时用用户环境变量。普通聊天、普通输入卡、截图、项目配置、命令参数、日志与分享包均不接收密钥。
4. 使用官方 API 只读核验密钥授权和目标文库，再执行已授权的分类创建或导入。只报告是否读到凭据及授权结果。若需要定时，另核验调度进程能否读取凭据和访问 API；手动成功不等于定时验收。云端条目可先在网页文库查看，桌面端下次同步后显示。

参考 [Zotero 本地 API](https://www.zotero.org/support/dev/web_api/v3/local_api) 和 [Zotero Web API 写入](https://www.zotero.org/support/dev/web_api/v3/write_requests)。

### 默认分类结构与回读

默认在用户确认的文库中使用与周刊同名的父分类，例如“教育研究周刊 → 11.20”。按刊物时区的正式期次日期生成 `月.日`（不补零），补导使用原期次日期。已配置父分类时沿用，并核对实际文库、父分类名称与 ID。按名称和父子关系查找，唯一且身份明确时复用；缺失时通过当前模式的受支持写入方式自动创建。父分类也缺失时，仅在目标文库和建刊授权明确后创建；不自动转入其他文库或分类。

新建后按实际 ID 读回名称、父子关系和唯一性，再归档。若跨年同名无法核准或有多个匹配，暂停该分类的写入，请用户明确目标或改用含年份的命名。读取失败或写入状态不明时先查实际状态，避免重复创建。分类和导入分别记录“已核验”或待办及原因；发布可独立完成。

## 定时

先核对现有任务身份、频率、时区、运行目录、结果交付位置和读写权限；复用正确的已有任务。任务应读取项目配置和最新历史，避免把下一期编号、绝对路径、特定机器的集合ID写死在通用技能里。定时器创建成功与无人值守可执行是两个结果，首次真实触发后分别验收检索、工作区、发布与文献库连接。

## 发布与失败恢复

隔离草稿、冻结模拟和正式历史。发布前核对当前期次是否已有正式文件，确保正式名单与读者版、历史和导入清单一致。保存实际截止、证据、未覆盖来源以及失败阶段。发布或导入中途断开时，从最后确认状态恢复，避免整期重复发布或重复创建文献库记录。共享技能或报告时，去除账户、任务标识、个人路径和无权转发的原文。

# 逐题引导

适用于明确创建新刊、无配置且首次只说“帮我追踪一下最新文献”，以及仅给出一个宽泛学科的调用。先读已有配置和本轮上下文，保留已答事项。

- 明确要建刊：从第一个未答设置开始。
- 意图模糊：先问“你想创建持续更新的周刊，还是只做一次文献简报？”给“创建周刊”“只做一次”两个选项。用户已明确意图则跳过。
- 只做一次时，仅补齐决定检索范围的问题。只给“化学”之类学科名时，记录为学科，继续用研究方向多选卡，可提供“全学科概览”选项。用户明确选择概览，或已提供足够具体的主题，才开始当期论文检索。单次简报无需填写建刊的周期、格式或 Zotero 设置，除非用户另有要求。

## 一次只问一题

- **直接调用原生提问工具。** 在 Codex 默认模式优先调用 `functions.request_user_input_async`，传入 `questions` 数组且恰好一项。研究方向和候选来源优先使用下文的原生多选表单，每张表单只处理一个问题。自由输入题只传 `title`；选择题另传简短 `options`。计划模式若只提供 `functions.request_user_input`，用它的单题格式。没有相应工具或调用失败时，才在聊天中单独发当前题，并明确当前界面未能打开输入卡片。
- 异步调用返回只表示题目已提交。等收到用户回复事件或明确的聊天答复，再更新设置和问下一题。工具成功提交后，聊天正文不重复提问。预选项、超时和题目发出均不视作用户选择；若回合需结束，可仅提示“请在输入卡片中回答”。
- 引导尚有必要选项未答时，可整理配置、核对期刊与会议入口，暂缓当期论文检索、创建定时任务和 Zotero 写入。方向清晰后再按用户确认的建刊或单次方案执行。
- 用户一次主动回答多个设置时全部记录。回答“不确定”时，可在下一张卡片给当前题的简短选项，或接受用户委托由助手拟定默认值。学科、方向、周期、定时、是否用 Zotero 与目标分类各自分题。

## 建议顺序

按已知信息和上一个答案跳过不适用的问题。下列清单是助手的流程，用户每轮只看到当前题。

1. 学科：“你想做哪门学科的周刊？”
2. 研究方向：使用下文的研究方向多选卡。
3. 候选来源：使用下文的候选来源多选卡。
4. 语种：有实际取舍且尚未确定时单独问。
4a. 阅读偏好（首次建刊可选）：在来源与语种之后，另发一张单选卡问“当论文质量和相关度相近时，要略微优先推荐哪一类？”选项为“不设偏好”“中国国内期刊（投稿参考）”“中文文献”“自定义地区或语种”。可跳过，未选择则不设偏好。已明确回答时直接记录；选自定义后单独询问具体范围。区分国内期刊与中文文献，不能从选择中文检索或中文交付推断此偏好。保留现有 Zotero 必问规则。
5. 更新频率：“你希望每周出一期，还是每两周出一期？”
6. 运行方式：“你想手动生成，还是设置定时任务？”选定时后，若缺安排，只在后续每轮问一个必要事项（运行时间、时区或交付位置）。
7. 格式：“你希望用 PDF 还是 Markdown？”已有偏好就跳过。刊名可按学科拟定。
8. Zotero（首次建刊必问，已明确回答则跳过）：在确认交付格式后，用原生单选卡问“你希望怎样归档每期正式荐读？”选项为“暂不启用”“本地 Zotero”“Zotero 云端”。卡片预选不算回答，必须等到实际提交或用户明确用文字作答。当前卡片不可用时，只在聊天问这一题。用户选本地或云端后给出 [对应配置指引](integrations.md#zotero-本地与云端模式)。启用时默认“周刊名 → 月.日”，已有目标沿用，只有目标不清楚时另起一轮追问。记录实际选择和连接状态，密钥只走保密入口。

短对话示例：用户说“帮我创建一个周刊”，助手回复“你想做哪门学科的周刊？”并等待。用户答“教育学”，下一轮才发教育学研究方向多选卡。用户若已说“教育学，每两周，手动生成，不用 Zotero”，直接从研究方向问起，后面跳过已回答的题。

## 研究方向与来源范围

两步各用一张卡。每张卡包含一个真正的复选组，最后一项固定为“其他（请填写下方）”，以及同张卡下方的可选文本框。用户可以同时勾选多个已有选项和“其他”，填写补充后一次提交。每张卡只处理一个问题，无需另弹补充卡。原生表单不支持条件展开，文本框始终可见，提示“仅需补充时填写”。

- **研究方向**问“你感兴趣的研究方向有哪些？可多选。” 根据学科由助手给出约 4–6 个主流方向，每项用短名称并简述范围，保留末项“其他”。例如化学可列有机合成与催化、材料与能源化学、分析化学、物理与理论化学、化学生物学。文本框可填写方向或更细的子方向。单次简报如适用可在“其他”之前列“全学科概览”，仅在用户主动选择时采用。
- **候选来源**问“你希望从哪些来源筛选候选论文？可多选。” 按学科提供可组合的具体方案：国际顶刊（国际旗舰期刊及在线先发）、国内顶刊（国内该方向公认旗舰期刊）、顶尖会议论文（该领域有正式评审的主轨或论文集）、重要专业期刊（方向相关度高的领域刊）、预印本与工作论文（用作发现或前沿观察）。说明每项范围，可给有把握的简短例子；对不以会议论文为主要发表方式的学科，准确说明会议的作用。文本框可补必追或排除的期刊、会议、数据库及语种。按所选方案和补充核对正式入口，拟定监测清单。来源选择不改变单篇论文的筛选与评级。

优先直接调用 `mcp__data__form_elicitation_v2_request`。一次调用放两项：首项 `type: "multi_select"`，稳定选项 ID，末项 ID 为 `other`；次项 `type: "text"`，标题“补充（选填）”。两项均设 `required: false`。以提交返回的实际 ID 数组和文本为准。即使漏勾“其他”，也采纳用户填写的文本。若只选“其他”而缺必要信息，再补问一个短问题。取消后等待用户指示；空提交不视作接受默认。

若当前只有单选工具，用同一张自由输入卡列编号，允许“1、3；其他：……”一次提交，并说明当前界面不能勾选多项。原生提问工具均不可用时才在聊天发同样的一题。

## 保存并开始

首次建刊时，Zotero 模式是必答的配置项。用户未明确选择时必须发卡并等待实际答复，不能用预选项、默认值、空提交、取消或超时代替。用户已明确说不用 Zotero、选本地或选云端时可直接记录。模式未确认时保持建刊待续，不能生成或发布首期、保存为正式配置或启用定时任务。可先核对来源或保存草稿。已选模式但尚未连通的，按已选模式记待配置，照常完成建刊与出刊。

收齐必要设置后，用简短摘要呈现方案。若尚需确认，只问“按这套方案创建吗？”。用户已授权采用方案时直接保存；不要要求用户重述答案。配置保存在新刊项目中，沿用已有约定，或使用 `literature-profile.json`，记录学科、方向、词和来源、时效、周期与手动／定时模式、输出、Zotero 模式、归档状态和必要目标。授权创建定时任务或写入 Zotero 时按集成协议执行。已要求首期则继续制作；只要求配置则交付启动方式。已有周刊出下一期直接读配置。

## 建刊后给用户的筛选说明

首次建刊配置确定并保存后，给用户一次简短的筛选说明。若接着制作首期，先在聊天中发这段说明；若仅建刊，把它放在建刊完成消息中。它是告知，不另开一题或要求确认。后续常规出刊无需重复发送。

用当前项目实际采用的规则写四条短句。若启用了地区或语种阅读偏好，在“怎么筛”里补一句说明其适用范围：

- **怎么筛**：核对近期进展、发表状态和版本，再看研究设计、证据、局限及方向相关度。期刊或会议层级是线索。合适的论文可以是零篇。
- **星级**：表示初步阅读优先级。启用时，按 [运行协议](protocol.md) 或项目已有定义简述一到五星。关闭时说明本刊采用阅读标签和核验等级。
- **阅读标签**：精读候选值得后续细读，泛读适合快速了解，暂存留待补证。未经可靠评审且缺乏强独立验证的稿件限泛读或暂存。
- **核验 A/B/C**：A 检查过关键正文、方法与结果，B 只核到部分正文或详实稿本，C 仅核对书目、发表信息与摘要。C 级精读候选会注明正文待核验。
